# Политика безопасности

## Сообщить об уязвимости

Если вы нашли уязвимость безопасности в проекте Factum, **пожалуйста,
не открывайте публичный issue**.

Отправьте отчёт приватно одним из способов:

- GitHub Security Advisories: вкладка **Security → Report a vulnerability**
  в репозитории.
- Email на адрес, указанный в профиле владельца репозитория.

В отчёте укажите:

1. Версия проекта (см. `package.json`, поле `version`).
2. Шаги воспроизведения (curl / HTTP-запросы / последовательность
   действий в UI).
3. Влияние (что может сделать атакующий).
4. (Опц.) Предлагаемое исправление.

Мы ответим в течение 5 рабочих дней. После исправления и выпуска
патча мы упомянем вас в описании релиза (если вы дадите согласие).

## Поддерживаемые версии

| Версия | Поддерживается          |
| ------ | ----------------------- |
| 0.3.x  | security fixes only     |
| < 0.3  | не поддерживается       |

## Что считается уязвимостью

- Обход аутентификации или авторизации (доступ к `/api/admin/*` без
  роли `admin`, доступ к чужим проектам через `/api/history/[id]`).
- SSRF-обход `validateUrl()` (доступ к приватным диапазонам, cloud
  metadata endpoint).
- SQL-инъекция (через `$queryRawUnsafe` или иное).
- XSS через `dangerouslySetInnerHTML` / `innerHTML` / несанированный
  ввод.
- Утечка `AUTH_SECRET`, `LLM_API_KEY`, `passwordHash` в логи или
  ответы API.
- Race condition в bootstrap-администратора, приводящий к созданию
  admin/admin при пустом `ADMIN_PASSWORD`.

## Что не считается уязвимостью

- In-memory rate-limiter, сбрасываемый рестартом (задокументировано в
  README, в разделе «Известные ограничения»).
- DNS rebinding TOCTOU (задокументировано).
- Блокировка поиска HTML-парсингом при смене разметки (деградация
  штатная, не безопасность).

Спасибо за ответственное раскрытие.
